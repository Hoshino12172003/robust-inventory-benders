# Hybrid v8 自适应归一化割实验报告

## 1. 最终候选算法

Hybrid v8保留完整场景块与Benders/Farkas可行性割两种机制。每轮完整分离后，算法按原始违反量排序，将最多4个最严重场景作为完整共同追索块加入主问题。对于未提升场景，算法将Farkas割按最大绝对系数归一化，并选择归一化违反效力最高的一条候选割。只有当该效力不低于预先冻结的0.10门槛时，才将该割加入主问题；若该场景以后被提升为完整场景块，则删除其已有割。终止前仍执行全部42个场景的精确分离认证。

因此，v8不是将算法改名为Batch-4 CCG。完整场景块负责快速覆盖最严重场景，归一化割负责在效力足够高时用轻量线性约束补强主问题，效力门槛用于避免低质量割扰乱MIP搜索。割是自适应触发，而不是要求每一轮机械加入。

## 2. 静态“少块多割”筛选为何被否决

先行筛选测试了每轮1至3个完整场景块并配合1至10条普通Farkas割。20城市实例的迭代数由Batch-4的2轮增加到3至5轮，30城市实例增加到3至5轮，运行时间随之上升。原因是当前可行性割只排除候选点附近的不可行区域，不能稳定替代最关键场景的完整共同追索结构。v8因此保留最多4个完整场景块，不采用静态“少块多割”方案。

## 3. 开发阶段同批比较

在先前已经观察过的12个周度实例上，v8与标准单场景纯CCG采用交替顺序同批运行。v8为12/12认证，纯CCG为11/12认证。在双方均认证的11组中，v8为11胜0负，平均运行时间为31.96秒，纯CCG为48.82秒，平均时间下降34.53%，几何平均加速比为1.682。11组同向结果的精确双侧符号检验描述性p值为0.00098。v8相对完整Direct模型的最大目标绝对误差为6.18×10^-13。

这12个实例已参与过v4至v8开发，只能作为开发证据，不能单独承担外部确认结论。12组中仅1组实际触发了归一化Farkas割。

## 4. 预封存的5周确认实验

在任何确认求解前，先将v8源码SHA-256固定为`AC98624CC509B6938DDB920FBCE901E1EF4F27DC1A76AA03E714547B81A45E13`，并冻结效力门槛、求解器设置、评价指标与运行顺序。确认集使用17个测试周中从未进入前述12周开发的剩余5周；10个实例与场景文件均在优化前生成并记录哈希。每组同时运行v8、标准单场景纯CCG、Batch-4 CCG和完整Direct模型。

| 周度实例 | v8时间（秒） | 纯CCG时间（秒） | Batch-4时间（秒） | v8割数 |
|---|---:|---:|---:|---:|
| 2018-04-30 | 35.964 | 52.572 | 35.961 | 0 |
| 2018-05-28 | 1.754 | 3.945 | 1.722 | 1 |
| 2018-06-25 | 28.027 | 50.155 | 27.626 | 0 |
| 2018-07-23 | 13.289 | 28.942 | 13.699 | 0 |
| 2018-08-20 | 1.564 | 3.974 | 1.552 | 0 |

三种分解方法均为5/5认证。v8相对纯CCG为5胜0负，平均运行时间为16.12秒，而纯CCG为27.92秒；几何平均加速比为2.007。5组全部同向的精确双侧符号检验p值为0.0625，因此小样本确认结果方向一致且效应明显，但单独按5组计算尚未达到0.05显著性水平。v8相对Direct目标的最大绝对误差为3.44×10^-7，低于采用的10^-6数值可行性量级。

## 5. 与Batch-4的强消融边界

封存确认中，v8与Batch-4均为5/5认证。v8为1胜4负，平均时间为16.1197秒，Batch-4为16.1121秒，几何平均速度比为0.9979；两者在实际意义上持平。唯一触发Farkas割的确认实例中，v8为1.754秒，Batch-4为1.722秒，也没有显示割带来独立加速。

因此，当前证据支持“最终Hybrid v8整体优于标准单场景纯CCG”，但不支持“Farkas割模块稳定优于无割的Batch-4”。相对纯CCG的主要速度来源仍是按违反程度一次提交多个完整场景块；自适应割机制的贡献是保留一般共同追索不可行性处理能力，同时通过效力门槛避免低效割造成明显性能损失。

## 6. 论文中允许采用的结论

可以写：

> 在预先封存的未使用周度实例上，所提出的自适应Hybrid框架保持了完整认证和Direct目标一致性，并在所有五个实例上快于标准单场景CCG。其主要计算收益来自违反度驱动的有界场景块提交；归一化Farkas割仅在效力达到门槛时触发，从而保留共同追索可行性处理能力，而不在低效情况下持续膨胀主问题。

不应写：

- Farkas割本身已被证明稳定加速；
- Hybrid v8显著优于Batch-4 CCG；
- 5个确认周足以证明对任意真实数据或任意不确定集都普遍占优；
- 未认证的纯CCG实例可以作为普通运行时间胜负样本使用。

## 7. 对既有论文实验的影响

既有487个冻结文件未被修改。如果论文将v8作为主算法，所有直接依赖算法实现的运行时间、迭代数、场景块数、割数、认证率和PAR-2表图需要用冻结后的v8统一重跑；模型公式、数据处理、成本锚点、Direct模型规模以及由精确最优解得到的管理结论不因调度策略改变而自动失效。在完成主文重跑前，不应覆盖旧实验，应将v8结果作为独立候选版本保留。
