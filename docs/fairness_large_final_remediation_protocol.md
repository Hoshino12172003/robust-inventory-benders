## Certified adaptive multi-cut rule

At the current master point, cache entries contain deviation patterns only. Every cached or pool-proposed scenario is rerun through current-point fixed-scenario primal/Farkas certification. No old ray, cut, violation value or certification is reused. Every master cut has its own current-point certificate. Only a complete separation solve with a legal objective bound may certify absence of a violating scenario.

Pattern identity uses schema `fairness_deviation_pattern_v1`. Formal component order is the Cartesian sequence `[(r,j) for r in instance.R for j in instance.J]`; `instance.R` and `instance.J` are the ordered model index sequences frozen by the instance, never sets, incidental dictionary order, solver pool order or filesystem order. Canonical IDs are Unicode NFC strings. Values are integer 0 or 1 and length is exactly `|R||J|`; otherwise fail closed. The payload contains `schema`, ordered `[region_id,product_id]` pairs and values. It is serialized by `json.dumps(payload,sort_keys=True,separators=(",",":"),ensure_ascii=False,allow_nan=False).encode("utf-8")`, with no BOM or trailing newline. `pattern_sha256` is the uppercase hexadecimal SHA256 of those bytes.

Cut identity uses schema `fairness_farkas_cut_v1`. Formal variable IDs are ordered as `y[i]` over `instance.I`, `x[i,j]` over `instance.I` then `instance.J`, followed by `T`; these IDs do not depend on Gurobi creation order or object identity. The payload includes schema, sense, every canonical variable ID and coefficient, constant, RHS, and Farkas normalization identity `nonnegative_multipliers_sum_to_one_v1`. Every numeric value is finite IEEE-754 binary64, `-0.0` is replaced by `+0.0`, and Python `float.hex()` is used; NaN and infinities fail closed. The same canonical JSON rule produces bytes and `cut_sha256` is uppercase hexadecimal SHA256. A cut hash is exact identity only; approximate redundancy never changes or rounds a hash.

Represent each certified cut in canonical `(y,x,T)` order as `g(z)>=0`. Raw violation is `max(0,-g(z_current))`; normalized violation is raw violation divided by `max(1,||a||_1)`. Direction similarity is cosine similarity of L2-normalized coefficient vectors; diversity is `1-max_similarity_to_selected`. Zero norms and nonfinite inputs fail closed.

Every selection metric is first converted to an integer bucket under schema `binary64_integer_ratio_round_half_even_v2`. For a finite binary64 value `v`, obtain `(n,d)=v.as_integer_ratio()`. A positive finite decimal quantum is frozen as the exact rational `q=Q_n/Q_d`; for the selection quantum, `Q_n=1` and `Q_d=10^9`. Compute `divmod(abs(n)*Q_d,d*Q_n)` with arbitrary-precision integers, round by comparing twice the remainder with the divisor, break an exact half toward the even quotient, and restore the sign. Binary64 division, Decimal context precision, locale and formatted decimal strings are forbidden. This covers the largest finite binary64, smallest normal and subnormal, and both signed zeros without overflow; `-0.0` maps to bucket zero. Nonfinite numeric identity, invalid quantum, non-binary64-compatible input, or quantization-schema mismatch respectively fail closed as `nonfinite_numeric_identity`, `invalid_quantum`, `invalid_binary64_input`, or `quantization_schema_mismatch` and are never converted to a fallback bucket.

Raw acceptance tolerance is `1e-7`; raw, normalized, relative-violation, cosine, diversity and LB-improvement quanta are all `1e-9`, two orders below the scientific feasibility tolerance. The deadband is two buckets and affects selection only, never mathematical feasibility or final certification. Raw violation is accepted only strictly above tolerance plus deadband. Relative normalized violation is eligible only strictly above `0.10` plus deadband. Cosine values at or above `0.98` minus deadband are conservatively redundant. Thus values inside either deadband cannot gain priority or add a numerically ambiguous cut.

### Relative normalized violation erratum

Schema `relative_normalized_violation_v1` uniquely defines the previously underspecified relative score. At iteration `k`, first form `V_k` from every allowed source: the primary/full-separation incumbent, the pattern cache, and the solution pool. Membership requires current `(x,T,B_rho)` fixed-scenario primal/Farkas certification, strict current-point violation above the raw acceptance tolerance, valid canonical cut identity, finite numeric identity, and normalized violation quantized at `1e-9`. Exact `cut_sha256` deduplication occurs across all sources before the denominator; duplicate occurrences merge their source labels and must agree on pattern SHA and normalized bucket. Uncertified, invalid, nonviolating or hash-inconsistent candidates fail closed or are excluded as prescribed and never affect the denominator. Relative eligibility precedes all cosine, diversity and redundancy filtering.

For each unique member `i`, let `N_i=bucket_1e-9(v_i)`, a nonnegative integer, and let `N_max=max(N_i for i in V_k)`. When `V_k` is empty, no denominator is computed, status is `no_certified_violating_candidates`, and eligible count is zero. When `V_k` is nonempty but `N_max=0`, no division occurs, status is `no_positive_quantized_normalized_violation`, and eligible count is zero. Neither status certifies robust feasibility; only the full separation objective bound may do so, otherwise the iteration is uncertified/fail-closed.

For `N_max>0`, compute exclusively with arbitrary-precision integers

`R_i = RoundHalfEven(N_i * 10^9 / N_max)`.

The integer operation uses `divmod(N_i*10^9,N_max)`, compares twice the remainder with `N_max`, and resolves an exact half to the even quotient. It performs no binary64 or Decimal-context division. The maximum candidate has `R_i=1,000,000,000`. Threshold `0.10` is identity bucket `100,000,000`; with the frozen two-bucket deadband, eligibility is strictly `R_i>100,000,002`. Direct comparison of normalized violation to `0.10`, per-source denominators, empirical denominators, or an undefined primary denominator is forbidden. Candidate input order and duplicate source occurrences cannot change `N_max`.

After relative filtering, and only then, apply the frozen cosine/diversity rules. Final ordering remains quantized normalized violation descending, quantized diversity descending, pattern SHA ascending, then cut SHA ascending. Similarity rejection never retroactively changes `N_max`.

Manifest and checkpoint identity include `relative_violation_schema`, quantum, threshold bucket, deadband buckets, denominator rule and denominator bucket. Per-candidate iteration/checkpoint evidence includes normalized bucket, relative bucket, eligibility, status, exact cut/pattern hashes and merged sources. Resume uses persisted integer buckets; recomputation is permitted only when every persisted value matches, otherwise it fails closed with `relative_violation_identity_mismatch`.

Exact hashes are deduplicated first. Primary-cut diversity is defined as one. Select the primary cut by quantized normalized violation descending, quantized diversity descending, pattern SHA ascending, then cut SHA ascending. Recompute quantized diversity after each selected cut and apply the same total order for every secondary choice. Raw violation controls strict current-point acceptance but is not an ordering key. Creation order, object addresses and solver pool order never break ties.

The only schedule count is `total_committed_unique_master_cuts`; the former name `total_certified_cuts` is forbidden and is not a recovery source. At the start of iteration `k`, let `C_k=|C_k^committed|`, where `C_k^committed` is the append-only, cut-SHA-unique sequence of valid cuts actually added to the current master and included in the last atomic checkpoint before iteration `k`. Certified-but-unselected, selected-but-uncommitted, duplicate, numerically redundant/rejected, invalid or uncertified cuts and pool/cache candidates do not count. The current iteration never changes `C_k` during selection.

The frozen maximum is `B(C)=5` for `C<1000`, `3` for `1000<=C<3000`, `2` for `3000<=C<5000`, and `1` for `C>=5000`; final certification always forces one. If the ordered eligible unique candidate count is `E_k`, then `A_k=min(E_k,B(C_k))`, and exactly the first `A_k` candidates are selected. If `E_k=0`, the selected list is empty, committed count is unchanged, and only the complete-separation outcome determines the next scientific state. Thus 999 uses five for that iteration even if one commit makes the next count 1000; 1000 uses three, 2999 uses three, 3000 uses two, 4999 uses two, and 5000 uses one. An expected post-commit count is never used early to choose a segment. These bands are frozen from the S1 evidence that fixed batch-5 produced excessive master growth. They cannot be changed from L0, L1, M1 or holdout outcomes. Wall-clock, solver runtime and CPU time remain reporting fields only: machine, operating-system, scheduling and solver noise make them invalid drivers of a cross-machine and resume-deterministic scientific path.

No cut deletion, retirement, deactivation or replacement is allowed. Adaptation controls only new rows. Every checkpoint identity hash covers the complete ordered `selected_cut_sha256_values`, append-only ordered `committed_master_cut_sha256_values`, `committed_cut_count_before_iteration`, `committed_cut_count_after_iteration`, `cut_commit_state`, reconstructable canonical cut payload map, schedule state and all canonicalization/quantization identities. Each list is SHA-unique; sorting a copy for set analysis is allowed but persisted commit order is never discarded. Duplicate list entries, count/list disagreement, an illegal selected/committed relation, missing or hash-mismatched payload, schema drift, or unknown state fails closed. The old ambiguous `cut_sha256_values` field is prohibited.

The commit state enum is `no_selection`, `selection_complete_not_committed`, and `commit_complete`. Selection ranks eligible candidates, freezes the first `A_k` hashes and their reconstructable canonical payloads, records before=after=`C_k` while leaving the committed list unchanged, and atomically writes `selection_complete_not_committed` before any master add. With no eligible cuts it writes `no_selection`. Commit rebuilds/uses the master at exactly the persisted committed list, revalidates each selected canonical payload and hash, adds selected cuts once in frozen order, and only after every add succeeds atomically writes `commit_complete`. The new committed sequence is the old sequence followed by selected hashes, so `C_{k+1}=C_k+|S_k\C_k^committed|=C_k+A_k` under normal pre-deduplication; after-count must equal committed-list length.

An interruption before the selection checkpoint reruns the same deterministic selection. After `selection_complete_not_committed` but before a durable commit checkpoint, recovery rebuilds only the `C_k` committed master, uses the saved selected hashes without reranking, and submits them once. After `commit_complete`, recovery rebuilds the complete committed list and advances; it never adds an existing SHA again. If one or all in-memory adds succeed but atomic checkpoint writing fails, the process stops, that volatile partial/all add is scientifically invisible, and recovery starts from the last persisted state in a newly rebuilt master. Partially committed checkpoints are forbidden. Identical persisted input therefore yields identical batch, ordering, selected hashes, committed hashes and next state.

Checkpoints also freeze iteration, quantized LB-improvement state, stall counter, pattern hashes, complete candidate ordering and duplicate/redundancy decisions. LB improvement is `max(0,current_LB-previous_LB)` bucketed by the same exact integer rule at `1e-9`; the stall counter counts consecutive zero buckets. Both are reporting-only and cannot alter batch size or cut selection. Runtime history is not reconstructed into scientific state.

Metadata records canonicalization schema versions, all quanta/deadbands, schedule, cumulative candidates, cache hits and recertifications, certified cuts, selected cuts, rejection reasons and active cuts. Each iteration records candidate/pattern/cut hashes, binary64 inputs and integer buckets for raw/normalized/relative violation, similarity and diversity, complete ordering keys, schedule segment, budget and trigger, selected count, active-cut count before/after, complete-separation status and objective bound, and initial-UB evidence identity. Master/separation/wall runtimes are reported separately and never appear in a selection key or branch predicate.
